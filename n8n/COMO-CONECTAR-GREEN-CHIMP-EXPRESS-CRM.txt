GREEN CHIMP EXPRESS | CONECTAR FLUJO PRINCIPAL + GOOGLE SHEETS AL CRM

Objetivo:
Que el CRM de la pagina siga recibiendo datos del flujo viejo de Google Sheets
y tambien del flujo principal nuevo que guarda en public.gc_leads_estado.

IMPORTANTE:
La pagina del CRM lee public.crm_leads.
El flujo principal nuevo guarda en public.gc_leads_estado, por eso hay que
sincronizar tambien hacia public.crm_leads.

DIAGNOSTICO CONFIRMADO CON EL FLUJO REAL:
- gc_leads_estado vive en la base configurada como "Postgres account 3".
- El CRM publicado usa otro proyecto de Supabase.
- Guardar Estado PostgreSQL y Guardar Estado PostgreSQL1 no sincronizan el CRM.
- Por eso Landing y Chatbot existen, pero el tablero muestra cero.

Sintoma que confirma que falta esta sincronizacion:
- El contacto aparece en el portal de conversaciones.
- Los nodos Guardar Estado PostgreSQL, Guardar Estado PostgreSQL1 y Log Saliente1
  terminan bien.
- Pero el tablero Green Chimp Express no sube el contador y el lead no aparece.

En ese caso no fallo WhatsApp ni el bot: falta mandar el mismo lead a
public.crm_leads con el RPC upsert_crm_lead_from_sheet.

Tambien existe una segunda proteccion desde Supabase:
supabase/sync-green-chimp-wa-conversations-to-crm.sql

Ese SQL crea un trigger para que cada conversacion nueva de Green Chimp
Express en public.wa_conversaciones se refleje automaticamente en
public.crm_leads, aunque n8n solo haya guardado la conversacion.

Proteccion adicional para Woolrich / Especialidades Dentales:
supabase/route-crm-leads-by-known-company.sql

Ese SQL carga la lista de subscriber_id conocidos de Woolrich desde
Woolrich_N8N.xlsx y crea un trigger en public.crm_leads. Si un flujo manda
uno de esos contactos a otra empresa por error, Supabase lo enruta de nuevo
a dr-woolrich antes de guardarlo.

1. En el flujo principal de n8n, agrega un nodo Code despues de:
   Guardar Estado PostgreSQL

2. Ponle este nombre:
   Preparar CRM Green Chimp Express

3. Copia dentro de ese nodo el codigo de:
   n8n/green-chimp-express-main-flow-crm-sync.js

4. Despues agrega un nodo HTTP Request:
   Nombre:
   Upsert Green Chimp Express CRM

   Method:
   POST

   URL:
   https://nocbqbasbqkmezohhppd.supabase.co/rest/v1/rpc/upsert_crm_lead_from_sheet

   Headers:
   apikey: TU_SERVICE_ROLE_KEY
   Authorization: Bearer TU_SERVICE_ROLE_KEY
   Content-Type: application/json

   Body:
   JSON
   ={{ $json }}

5. Conecta asi:
   Guardar Estado PostgreSQL
   -> Preparar CRM Green Chimp Express
   -> Upsert Green Chimp Express CRM
   -> Guardar Estado PostgreSQL1

   La conexion debe quedar antes de Guardar Estado PostgreSQL1 para que el
   flujo conserve el orden:
   estado comercial -> CRM del tablero -> conversacion -> respuesta/logs.

RECUPERAR LOS CONTACTOS QUE YA EXISTEN

1. Crea un flujo manual temporal en n8n.

2. Agrega un nodo PostgreSQL llamado:
   Leer gc_leads_estado para CRM

   Credencial:
   Postgres account 3

   Query:
   n8n/green-chimp-express-backfill-query.sql

3. Agrega un nodo Code llamado:
   Preparar recuperación CRM Green Chimp

   Modo:
   Run Once for All Items

   Código:
   n8n/green-chimp-express-backfill-from-gc.js

4. Agrega un HTTP Request idéntico a "Upsert Green Chimp Express CRM":
   POST https://nocbqbasbqkmezohhppd.supabase.co/rest/v1/rpc/upsert_crm_lead_from_sheet
   Body JSON: ={{ $json }}

5. Ejecuta el flujo manual una sola vez. El RPC usa upsert, así que no duplica
   contactos si alguno ya existe.

6. Deja prendido el flujo viejo de Google Sheets si todavia lo necesitas.
   Ambos pueden convivir porque el RPC hace upsert por:
   company_key + subscriber_id

7. Si el flujo viejo de Google Sheets trae la etapa CLIENTE CONCRETADO,
   agrega estas dos entradas en su normalizador de etapas:

   VALID_STAGES:
   'cliente_concretado'

   aliases:
   cliente_concretado: 'cliente_concretado',
   concretado: 'cliente_concretado',
   cliente_activo: 'cliente'

Notas:
- Si el lead ya fue movido manualmente en el CRM, el RPC respeta stage_locked.
- El flujo principal manda crm_sync_source = flujo_principal dentro de raw_payload.
- El flujo viejo de Google Sheets conserva su raw_payload de Sheets.
- No pegues service_role en GitHub. Solo va dentro de n8n.
- Para sitio web, el adaptador manda classification = LANDING.
- Para chatbot, el adaptador manda classification = CHATBOT.
- Si llega etapa "Calificando", se guarda como kanban_stage = calificando.
